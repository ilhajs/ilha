`@ilha/model` holds one island's state in a single model. You describe transitions in `update`, side effects as return values, and rendering in `view`.

It is a separate package from `ilha`. Add it when one island owns enough messages to deserve a single loop. Plain `atom()` keeps working for everything else.

## Install

```package-install
@ilha/model
```

`ilha` and `effect` are peer dependencies.

## Define the loop

You define the initial model, one pure `update`, and a pure `view`. Event handlers report facts with `dispatch`, and `update` decides what each fact means.

```tsx twoslash
import { Data, Match } from "effect";
import { defineApp } from "@ilha/model";
import type { Dispatch } from "@ilha/model";

type Message = Data.TaggedEnum<{
  Decrement: {};
  Increment: {};
}>;
const Message = Data.taggedEnum<Message>();

interface Model {
  readonly count: number;
}

const update = (model: Model, message: Message) =>
  Match.value(message).pipe(
    Match.tag("Decrement", () => ({ model: { count: model.count - 1 } })),
    Match.tag("Increment", () => ({ model: { count: model.count + 1 } })),
    Match.exhaustive
  );

const view = (model: Model, dispatch: Dispatch<Message>) => (
  <div>
    <p>{model.count}</p>
    <button type="button" onclick={() => dispatch(Message.Decrement())}>
      -
    </button>
    <button type="button" onclick={() => dispatch(Message.Increment())}>
      +
    </button>
  </div>
);

const app = defineApp({ init: () => ({ count: 0 }), update, view });

export const Counter = app.component;
```

Mount `Counter` like any component: `mount(host, Counter)` or `await renderToString(Counter)`. The model atom snapshots like any other atom, so SSR and hydration work unchanged.

Keep messages serializable data: records of what happened, never callbacks or class instances. Name them for their cause (`ClickedSave`, `SucceededFetchUser`), and keep `update` pure so every transition stays testable.

## Send one-shot work

`update` returns the next model plus optional commands. A command is an `Effect` that resolves to a follow-up message or nothing. The runtime runs commands independently of each other.

```tsx twoslash
import { Data, Effect, Match } from "effect";
import { defineApp } from "@ilha/model";

type Message = Data.TaggedEnum<{
  AddBonus: { readonly amount: number };
  FetchBonus: {};
}>;
const Message = Data.taggedEnum<Message>();

interface Model {
  readonly count: number;
}

const update = (model: Model, message: Message) =>
  Match.value(message).pipe(
    Match.tag("FetchBonus", () => ({
      cmd: Effect.succeed(Message.AddBonus({ amount: 10 })),
      model,
    })),
    Match.tag("AddBonus", ({ amount }) => ({
      model: { count: model.count + amount },
    })),
    Match.exhaustive
  );

const view = (model: Model) => <p>{model.count}</p>;

export const app = defineApp({
  init: () => ({ count: 0 }),
  update,
  view,
});
```

Provide extra services inside the command with `Effect.provide`. Map every failure into a message with `Effect.catch`; anything that escapes is logged and the island keeps running.

Start-up work belongs in a subscription with constant dependencies that emits once, rather than in `init`.

## Listen to ongoing work

A subscription is a stream whose lifetime follows a slice of the model. When the dependencies change, the old stream stops and a new one starts. When the island unmounts, the stream stops too.

```tsx twoslash
import { Stream } from "effect";
import { defineApp } from "@ilha/model";

type Message = Data.TaggedEnum<{ Tick: {} }>;
const Message = Data.taggedEnum<Message>();

interface Model {
  readonly count: number;
  readonly on: boolean;
}

const view = (model: Model) => <p>{model.count}</p>;

export const app = defineApp({
  init: () => ({ count: 0, on: true }),
  subscriptions: [
    {
      deps: (model: Model) => model.on,
      stream: (on) =>
        on === true
          ? Stream.tick("1 second").pipe(Stream.map(Message.Tick))
          : Stream.empty,
    },
  ],
  update: (model: Model, message: Message) =>
    message._tag === "Tick" ? { model: { count: model.count + 1 } } : { model },
  view,
});
```

Keep dependencies small JSON-shaped values so equivalent slices keep the stream alive. A subscription never runs on the server; server output reflects the `init` model only. Streams that fail stop quietly, so convert errors into messages inside the stream.

## Split a child out

A child owns its model and messages; the parent stores the child model, wraps child messages, and delegates with `foldChild`. The parent never edits the child slice directly.

```tsx twoslash
import { Data, Match } from "effect";
import { defineApp, foldChild } from "@ilha/model";
import type { Dispatch } from "@ilha/model";

type ChildMessage = Data.TaggedEnum<{ Bump: {} }>;
const ChildMessage = Data.taggedEnum<ChildMessage>();

interface Child {
  readonly n: number;
}

const childUpdate = (model: Child, message: ChildMessage) =>
  Match.value(message).pipe(
    Match.tag("Bump", () => ({ model: { n: model.n + 1 } })),
    Match.exhaustive
  );

type ParentMessage = Data.TaggedEnum<{
  Child: { readonly message: ChildMessage };
}>;
const ParentMessage = Data.taggedEnum<ParentMessage>();

interface Parent {
  readonly child: Child;
}

const foldChildState = foldChild<Parent, ParentMessage, Child, ChildMessage>({
  read: (model) => model.child,
  toParentMessage: (message) => ParentMessage.Child({ message }),
  update: childUpdate,
  write: (model, child) => ({ ...model, child }),
});

export const app = defineApp({
  init: () => ({ child: { n: 0 } }),
  update: (model: Parent, message: ParentMessage) =>
    message._tag === "Child"
      ? foldChildState(model, message.message)
      : { model },
  view: (model: Parent, dispatch: Dispatch<ParentMessage>) => (
    <button
      type="button"
      onclick={() =>
        dispatch(ParentMessage.Child({ message: ChildMessage.Bump() }))
      }
    >
      {model.child.n}
    </button>
  ),
});
```

Name each wrapper `Got*`, such as `GotSettingsMessage`. Combine sequential steps on one model with `combine`.

## Test the loop

`update` is a plain function, so test transitions without rendering. Drive the view with [`ilha/test`](/guide/recipes/testing) when people must reach the behavior through clicks.

```tsx twoslash
import { expect, test } from "bun:test";
import { Data, Match } from "effect";

type Message = Data.TaggedEnum<{ Increment: {} }>;
const Message = Data.taggedEnum<Message>();

const update = (model: { count: number }, message: Message) =>
  Match.value(message).pipe(
    Match.tag("Increment", () => ({ model: { count: model.count + 1 } })),
    Match.exhaustive
  );

test("increment adds one", () => {
  const next = update({ count: 0 }, Message.Increment());
  expect(next.model).toEqual({ count: 1 });
  expect(next.cmd).toBeUndefined();
});
```

## Know the limits

`@ilha/model` covers the core loop: model, messages, commands, subscriptions, and submodels. It deliberately leaves out a DevTools overlay (use [`ilha/debug`](/guide/devtools) plus the message flow), route biparsers (routes stay in your router; the route is just a model field), and async-data, field, machine, and query values. Those arrive as later value helpers; nothing here needs to change to adopt them.
