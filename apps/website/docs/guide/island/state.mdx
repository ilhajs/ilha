title: Local state
description: Declare reactive state local to an island with state(), read and write it, and initialize from props.
---

Declare island-local reactive state with `state()`. When a state value changes, the island rerenders automatically — only the island updates, nothing outside it is touched.

```tsx twoslash
import { ilha, state } from "ilha";

const Counter = ilha(() => {
  const count = state(0);
  return (
    <button onclick={() => count.update((value) => value + 1)}>
      {count()}
    </button>
  );
});
```

## Reading and writing

`state()` returns a signal accessor — call it to read, use `.set()` / `.update()` to write:

```ts twoslash
import { state } from "ilha";

const count = state(0);

count(); // read → returns current value
count.set(5); // write → sets value to 5
count.update((previous) => previous + 1); // update from the latest value
```

Use the updater form when the next value depends on the previous value. Ilha calls the function once with the latest value and writes its return value.

If the value itself is a function, pass the replacement to `.set`:

```ts twoslash
import { state } from "ilha";

const myCallback = () => "initial";
const nextCallback = () => "next";

// A lazy initializer may return a function value:
const callback = state(() => myCallback);
// Write a replacement with `.set`:
callback.set(nextCallback);
```

## Lazy initializers

Pass a function as the initializer to defer expensive work until the instance is created:

```tsx twoslash
import { state } from "ilha";

const expensiveInitialValue = () => 42;
const count = state(() => expensiveInitialValue());
```

The initializer runs once, when the island mounts.

## Initializing from props

Initialize state from a prop. The initializer applies only when the instance is created — later prop changes rerender the component but do not reset state:

```tsx twoslash
import { ilha, state } from "ilha";

const Counter = ilha<{ start: number }>(({ start }) => {
  const count = state(start);
  return <p>{count()}</p>;
});
```

## Separate instances do not share state

Each mounted instance keeps its own state slots. Two copies of the same island on a page are fully independent:

```tsx twoslash
import { ilha } from "ilha";

const Counter = ilha(() => <p>counter</p>);
const App = ilha(() => (
  <>
    <Counter />
    <Counter />
  </>
));
```

## Rendering state in JSX

Render a signal accessor directly in JSX; ilha calls it and HTML-escapes the result:

```tsx twoslash
import { ilha, state } from "ilha";

const Label = ilha(() => {
  const label = state("<b>hello</b>");
  return <p>{label()}</p>;
});
```

Calling `label()` explicitly works the same way inside JSX.

## Nested selection

To update a nested slice of an object or array without replacing the whole value, use `.select()`. Both a selector function and a property path are supported, and both stay writable:

```tsx twoslash
import { context } from "ilha";

const user = context("shared.user", {
  profile: { name: "Ilha" },
});
const nameA = user.select((value) => value.profile.name);
const nameB = user.select("profile", "name");
```

The selector (or path) must traverse nested state. Writes update only that path — siblings stay intact.

## Sharing state across islands

`state()` is local to one island instance. To share a value across multiple islands, use a [`context()` signal](/guide/island/signals) instead.
