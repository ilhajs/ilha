Ilha is alien-signals native. Every reactive value in Ilha — `state()`, `derived()`, `context()` — is an accessor over the same tiny signal engine, so one mental model covers all of them. You can also use alien-signals' own helpers (`signal`, `computed`, `effect`) inside islands; they participate in Ilha's reactive graph.

You rarely need them, though. Reach for Ilha's primitives first:

| Primitive            | Where            | Purpose                                             |
| -------------------- | ---------------- | --------------------------------------------------- |
| `state(initial)`     | Inside an island | Island-local reactive state                         |
| `derived(fn)`        | Inside an island | Sync, async, or streamed values computed from state |
| `action(fn)`         | Inside an island | Operations with `.pending` / `.data` / `.error`     |
| `effect(fn)`         | Both             | Reactive side effects                               |
| `context(key, init)` | Module scope     | Named global signal shared across islands           |
| `batch(fn)`          | Anywhere         | Group writes into one propagation pass              |
| `untrack(fn)`        | Anywhere         | Read without subscribing                            |

---

## Island-local: `state()` and `derived()`

Inside an island, use `state()` for local state and `derived()` for computed values. Slots persist across rerenders and are snapshot-restored on hydration:

```tsx twoslash
import { derived, ilha, state } from "ilha";

const CartBadge = ilha(() => {
  const items = state<string[]>([]);
  const count = derived(() => items().length);
  return <span>{count()}</span>;
});
```

See [State](/guide/island/state) and [Derived](/guide/island/derived).

## Shared across islands: `context(key, initial)`

`context()` creates a **named global signal**. Identical keys always return the same instance, which makes it useful for app-wide singletons (theme, locale, cart):

```tsx twoslash
import { context, ilha } from "ilha";

const cartCount = context("cart.count", 0);

const CartButton = ilha(() => {
  const addToCart = () =>
    cartCount.update((count) => count + 1);
  return <button onclick={addToCart}>Add to cart</button>;
});

const CartBadge = ilha(() => <span>{cartCount()}</span>); // [!code highlight]
```

Both islands share the same signal. Clicking the button updates the badge without any wiring between them.

### Accessor shape

Every accessor reads when called bare and writes through `.set()` / `.update()`:

```ts twoslash
import { context } from "ilha";

const count = context("ui.count", 0);

count(); // → 0  (read)
count.set(5); // sets to 5 (write)
count.update((previous) => previous + 1); // updates from the latest value
```

The updater form works on all accessors. If a signal stores a function, pass the replacement to `.set`: `callback.set(nextCallback)`.

### Use context in `bind:` bindings

Context accessors work anywhere a local state accessor does, including `bind:` template syntax:

```tsx twoslash
import { ilha, context } from "ilha";

const query = context("search.query", "");

const SearchInput = ilha(() => (
  <input
    type="search"
    value={query()}
    oninput={(event) => query.set(event.currentTarget.value)} // [!code highlight]
  />
));

const SearchResults = ilha(() => <p>Results for: {query()}</p>);
```

### Initialization is first-write-wins

The type and initial value are fixed at first call. Later calls with the same key return the existing signal:

```tsx twoslash
import { context } from "ilha";

const count = context("ui.count", 0); // creates signal<number>
const same = context("ui.count", 999); // returns same signal, ignores 999
```

Define context signals in a shared module to keep initialization consistent:

```ts twoslash
// contexts.ts
import { context } from "ilha";

export const theme = context("app.theme", "light");
export const userId = context(
  "app.userId",
  null as string | null,
);
export const sidebar = context("ui.sidebar", true);
```

### SSR behavior

`context()` is safe to call during SSR. The registry is module-level, so signals persist for the lifetime of the process. In a server environment where requests share the same module instance, be careful not to store user-specific state in context signals — use [`derived()`](/guide/island/derived), props, or local `state()` for per-instance data instead.

### Releasing entries — `context.delete()` and `context.clear()`

The registry is otherwise append-only. Long-lived SPAs that mint dynamic keys, HMR cycles, and tests all need a way to release entries:

```ts twoslash
import { context } from "ilha";

context.delete("cart.count"); // → true if it existed, false otherwise
context.clear(); // remove every context signal
```

Deleting a key does not affect accessors already handed out — they keep working against their original signal. It only means the next `context(key, initial)` call creates a fresh signal instead of returning the old one.

```ts twoslash
import { context } from "ilha";

const first = context("ui.count", 0);
first.set(5);

context.delete("ui.count");
const second = context("ui.count", 0); // fresh signal, starts at 0

first(); // → 5, unaffected by the delete
second(); // → 0
```

## Using alien-signals directly

Because Ilha is built on [alien-signals](https://github.com/stackblitz-labs/alien-signals), its primitives are available inside islands too:

```ts twoslash
import { computed, signal } from "alien-signals";

const base = signal(1);
const doubled = computed(() => base() * 2);

doubled(); // → 2
base.set(3);
doubled(); // → 6
```

Reading these inside an island render subscribes the island just like `state()`. Prefer `state()` / `derived()` / `context()` in application code — the raw engine is an escape hatch for library authors who want to share reactive state with non-Ilha code.

## `effect(fn)`

Runs a free-standing reactive effect outside any island. `fn` runs once immediately and re-runs whenever a signal it read changes.

```ts twoslash
import { context, effect } from "ilha";

const cart = context("cart.items", { count: 0 });

const stop = effect(() => {
  document.title = `${cart().count} items`;
});
```

Inside an island render, `effect()` registers an island effect slot; outside an island, it runs standalone. This page documents the standalone form.

### Cleanup and stopping

`fn` may return a cleanup function, invoked before each re-run and once more when the effect is stopped:

```ts twoslash
import { context, effect } from "ilha";

const delay = context("ui.delay", 1000);

const stop = effect(() => {
  const id = setInterval(() => console.log("tick"), delay());
  return () => clearInterval(id); // [!code highlight]
}) as () => void;

stop(); // disposes the effect and runs the final cleanup
```

### Implicit batching

Multiple synchronous signal writes inside the effect body produce a single propagation pass:

```ts twoslash
import { batch, context } from "ilha";

const a = context("t.a", 0);
const b = context("t.b", 0);

batch(() => {
  a(a() + 1);
  b(b() + 1); // both writes flush together
});
```

## `batch(fn)`

Runs `fn` as an atomic batch — multiple signal writes inside the callback produce a single propagation pass, so dependents (effects, deriveds, island re-renders) see the final state and run once instead of once per write. Returns whatever `fn` returns.

### Before and after

Without batch, each write triggers its own propagation pass:

```ts twoslash
import { context } from "ilha";

const a = context("b.a", 0);
const b = context("b.b", 0);

a.set(1); // → effects re-run
b.set(2); // → effects re-run again
```

With batch, both writes flush together:

```ts twoslash
import { batch, context } from "ilha";

const a = context("c.a", 0);
const b = context("c.b", 0);

batch(() => {
  a.set(10);
  b.set(20);
}); // → effects re-run once
```

### Implicit batching

`effect()` runs are batched implicitly, so you only need `batch()` when triggering multiple writes from outside an island — for example from a top-level event listener, a `setTimeout` callback, or a WebSocket message handler.

### Nesting

Nested `batch()` calls are safe and only flush when the outermost batch ends:

```ts twoslash
import { batch, context } from "ilha";

const count = context("d.count", 0);

batch(() => {
  batch(() => {
    count.set(1);
  }); // still inside outer batch — no flush yet
  count.set(2);
}); // outermost batch ends — single flush
```

## `untrack(fn)`

Runs `fn` with reactive tracking suspended. Reading signals inside `fn` returns their current value without subscribing the surrounding scope. Use this in effects or deriveds when you want to peek at state without causing a re-run on its changes.

### React to A, peek at B

The canonical pattern: an effect should re-run when `tracked` changes, but read `peeked` only as a one-off value:

```tsx twoslash
import { context, effect, ilha, untrack } from "ilha";

const tracked = context("u.tracked", 0);
const peeked = context("u.peeked", "hello");

const Island = ilha(() => {
  effect(() => {
    // Re-runs when `tracked` changes, but NOT when `peeked` changes.
    console.log(
      tracked(),
      untrack(() => peeked()),
    );
  });
  return <p>x</p>;
});
```

`untrack()` returns whatever `fn` returns, so it also works for peeking at derived values or any other reactive read:

```ts twoslash
import { context, untrack } from "ilha";

const s = context("u.s", 42);
const value = untrack(() => s()); // → 42, no subscription created
```

## `persist(accessor, key)`

Keep a standalone signal in sync with `localStorage`. On call it reads the key and writes the stored value into the signal, then subscribes and writes every change back — so a refresh and other tabs both stay in sync.

```ts twoslash
import { context, persist } from "ilha";

const cart = context("store.cart", [] as string[]);
persist(cart, "cart");
```

It is a no-op on the server (returns an inert unsubscribe), and it returns an unsubscribe you can call to stop syncing. Pass `{ storage, crossTab, serialize, deserialize }` to use a different backend or adapters.

## Notes

- Keys are global strings. Use namespaced keys like `"app.theme"` or `"cart.count"` to avoid accidental collisions across different parts of your app.
- Use `context.delete(key)` or `context.clear()` to release entries — useful in HMR, tests, or long-lived SPAs that mint dynamic keys. See [Releasing entries](#releasing-entries--contextdelete-and-contextclear).
- Context signals are not included in [`.hydratable()` snapshots](/guide/island/render#configure-hydration). If you need server-rendered context values on the client, pass them as island props and initialize the context signal inside [`effect.once()`](/guide/island/effect).
- Inside an island render, `effect()` registers an island effect slot; outside an island, it runs standalone. See [`effect(fn)`](#effectfn) above.
