title: Render and hydrate
description: Render islands to HTML with toString / toStringAsync, emit hydration markup with hydratable(), and mount them in the browser.
---

An island is a function component that returns JSX, a plain string, or a `RawHtml` object. Choose a server render API by whether you need async derived values and whether you want hydration markup.

| API                                       | Env    | Output                     |
| ----------------------------------------- | ------ | -------------------------- |
| `Island.toString(props)`                  | Server | Synchronous HTML           |
| `await Island.toStringAsync(props)`       | Server | Async HTML                 |
| `await Island.hydratable(props, options)` | Server | HTML plus hydration data   |
| `mount({ Island })`                       | Client | Discovers and mounts hosts |

## Return type

Prefer JSX for dynamic output — it escapes interpolated values and recomposes safely:

```tsx twoslash
import { ilha, raw } from "ilha";

const A = ilha(() => <p>Hello</p>);
const B = ilha(() => "<p>hello</p>"); // plain string for static markup
const C = ilha(() => <div>{raw("<em>trusted</em>")}</div>);
```

## Server rendering

Use `Island.toString(props)` for synchronous HTML. Use `await Island.toStringAsync(props)` whenever the island may resolve async derived values — it awaits them and pulls the first value from async-generator derived values:

```tsx twoslash
import { ilha, derived } from "ilha";

const Island = ilha(({ id }: { id: string }) => {
  const user = derived(async ({ signal }) => {
    const res = await fetch(`/api/users/${id}`, { signal });
    return res.json();
  });

  if (user.loading) return <p>Loading…</p>;
  return <p>{user()?.name}</p>;
});

const html = Island.toString({ id: "1" });
const asyncHtml = await Island.toStringAsync({ id: "1" });
```

Direct `Island(props)` calls are reserved for child composition inside another island render.

## Emit hydration markup

`await Island.hydratable(props, options)` wraps the rendered HTML with serialized props and an optional state snapshot. The `name` must match the client registry key:

```tsx twoslash
import { ilha, state, mount } from "ilha";

const Counter = ilha(() => {
  const count = state(0);
  return <p>{count()}</p>;
});

// Server
const html = await Counter.hydratable(
  {},
  { name: "Counter", snapshot: true },
);

// Client
mount({ Counter });
```

`mount({ Counter })` discovers `[data-ilha="Counter"]`, restores its props and snapshot, then activates it. If the registry has no matching name, `mount()` skips the element.

### Configure hydration

```ts twoslash
interface HydratableOptions {
  name: string;
  as?: string;
  snapshot?: boolean | { state?: boolean; derived?: boolean };
  skipOnMount?: boolean;
}
```

| Option        | Default | Purpose                                                      |
| ------------- | ------- | ------------------------------------------------------------ |
| `name`        | —       | Match the key passed to `mount()`                            |
| `as`          | `"div"` | Choose the wrapper element                                   |
| `snapshot`    | `false` | Restore state and derived values instead of recomputing them |
| `skipOnMount` | `false` | Skip `effect.once()` when restoring an included snapshot     |

`snapshot: true` includes both state and derived values. Use `{ state: true, derived: false }` or the inverse for finer control. Without a snapshot, state initializers run again and `effect.once()` fires normally. Effects always run, even when `skipOnMount` is enabled.

Snapshots are **positional** — state and derived values restore by primitive order on the server and client, so the component must declare the same primitive sequence in both. The wrapper uses `data-ilha` for discovery, `data-ilha-props` for input, and `data-ilha-state` when a snapshot is included.

Keep props and snapshots plain and JSON-safe. In development, lossy snapshot values such as functions, `undefined`, `bigint`, non-finite numbers, and `Date` objects produce a warning because the restored value may differ.

## How hydration works

1. The server renders the component once inside a fresh request-local frame and emits HTML, serialized props, and an optional snapshot.
2. The client `mount()` reads `data-ilha-props` and `data-ilha-state` off the host, restores state and derived values positionally, and activates the island over the existing markup — no flicker.
3. Subsequent state changes rerun the component and morph the host DOM in place.

Per-instance state never leaks between requests: every SSR render creates a fresh primitive frame.

## What runs where

| Concern                      | Server                      | Client                |
| ---------------------------- | --------------------------- | --------------------- |
| Component                    | Yes                         | Yes, on re-render     |
| `derived()` sync             | Yes                         | Yes                   |
| `derived()` async            | Yes (awaited in async SSR)  | Yes                   |
| `derived()` async generator  | First value only (SSR pull) | Consumes continuously |
| `action()`                   | No-op (idle)                | Yes                   |
| `effect()` / `effect.once()` | No                          | Yes                   |
| `onError()`                  | No                          | Yes                   |
| Bindings / native events     | Reflected (no listeners)    | Wired                 |

## Escaping and safe values

JSX children and attributes are escaped by default. `null` and `undefined` render as empty strings; arrays flatten without commas. Use [`raw()`](/guide/recipes/helpers#render-trusted-markup) only for trusted markup you control.

## Attributes

JSX attributes are escaped. HTML boolean attributes render when `true`; `false`, `null`, and `undefined` omit them. Use `class` normally (`className` and `htmlFor` are normalized). A few attribute forms are restricted for security: `srcdoc`/`srcDoc` are always dropped, disallowed URL schemes are stripped, and a `style` object declaration is dropped whole if its value could smuggle extra declarations.

## Events and re-rendering

Use lowercase native event props for logic local to one element:

```tsx twoslash
import { ilha, state } from "ilha";

const Counter = ilha(() => {
  const count = state(0);
  return (
    <button onclick={() => count.update((v) => v + 1)}>
      {count()}
    </button>
  );
});
```

Reading a signal during rendering subscribes the island. When a subscribed value changes, ilha reruns the component with current props, reuses primitive slots, produces new HTML, and morphs the existing host DOM. Focus and selection survive, form-control live state is preserved, and child-island slot ownership is kept.

Event props keep their modifiers: `:once`, `:capture`, `:passive`, and `:abortable`.

## List rendering

Arrays of JSX results are joined without commas; do not call `.join("")`:

```tsx twoslash
import { ilha, state } from "ilha";

const List = ilha(() => {
  const fruits = state(["apple", "banana", "cherry"]);
  return (
    <ul>
      {fruits().map((fruit) => (
        <li>{fruit}</li>
      ))}
    </ul>
  );
});
```

## Keyed lists with `data-key`

Tag plain rendered list items with a `data-key` attribute to have the morph engine match elements by key and move them on reorder instead of rewriting content at each position — focus, selection, transitions, and imperative state survive the reorder:

```tsx twoslash
import { ilha, state } from "ilha";

const List = ilha(() => {
  const order = state(["a", "b", "c"]);
  return (
    <ul>
      {order().map((k) => (
        <li data-key={k}>{k}</li>
      ))}
    </ul>
  );
});
```

Always key identity-sensitive elements (`<iframe>`, `<video>`, `<audio>`, `<canvas>`, `<embed>`, `<object>`). For list items that are themselves child islands with local state, use `Island.key()` — it stabilizes the child slot identity rather than a plain element (see [Compose islands](/guide/island/compose)).

When outside code imperatively manages attributes on an element inside an island, list them in `data-morph-preserve` so re-renders do not overwrite or strip them.

## Fragments

Return siblings without an extra wrapper:

```tsx twoslash
import { ilha } from "ilha";

const Form = ilha(() => (
  <>
    <input name="email" />
    <button>Submit</button>
  </>
));
```

## Notes

- In server-rendered islands, import RPC actions from `@ilha/router/server` and pass them directly to event props. Bind item-specific arguments with `.with()`: `onclick={remove.with(task.id)}`. Arguments are validated JSON-safe at bind time and stored in the hydration manifest; they are sent only after a real user event. Handlers are never executed during server rendering — closures like `onclick={() => remove(id)}` are not probed, so they get no hydration manifest entry (plus a development warning). For a normal client island such a closure still runs on the client after mount; for a server-owned island whose implementation never ships to the browser, an unrecognized closure cannot be replayed and never runs at all. Use a direct action reference when server interactivity is needed.
- `.hydratable()` is always async: it awaits async derived values and snapshots values at the moment you call it.
- Direct `Island(props)` calls are child composition only, never top-level server rendering.
- `@ilha/router` emits hydration markup for you; call `.hydratable()` directly only in a manual SSR handler.
