---
title: Derived state
description: Compute values with derived(), including synchronous derivations, promises, and async generators with built-in loading and error envelopes.
---

Use `derived()` to compute a value that depends on state or props. Derived values re-run automatically when any reactive dependency they read changes. Read the result with the same call syntax as state:

```tsx twoslash
import { state, derived } from "ilha";
// Inside an island component:
const count = state(0);
const doubled = derived(() => count() * 2);
```

## Sync values

```tsx twoslash
import { ilha, state, derived } from "ilha";

const Cart = ilha(() => {
  const price = state(100);
  const qty = state(3);
  const total = derived(() => price() * qty());
  return <p>Total: {total()}</p>;
});
```

When any signal the derived function reads changes, the function re-runs and the island re-renders.

## The derived envelope

Every derived value exposes `loading`, `value`, and `error` on the accessor. Use these for async work:

| Property  | Type                 | Description                           |
| --------- | -------------------- | ------------------------------------- |
| `loading` | `boolean`            | `true` while the function is running  |
| `value`   | `T \| undefined`     | The last successfully resolved value  |
| `error`   | `Error \| undefined` | Set if the function threw or rejected |

```ts twoslash
import { state, derived } from "ilha";

const count = state(0);
const total = derived(() => count() * 2);

total(); // same as total.value when resolved
total.loading; // false for sync derived after first run
total.error; // undefined when no error
```

For synchronous derived values, `loading` is `false` after the first run and `()` returns the computed value directly.

## Async values

Pass an async function to fetch data or run any other asynchronous work. The envelope tracks progress while the promise is pending:

```tsx twoslash
import { ilha, derived } from "ilha";

const UserCard = ilha<{ userId: string }>(({ userId }) => {
  const user = derived(async ({ signal }) => {
    const res = await fetch(`/api/users/${userId}`, { signal });
    return res.json();
  });

  if (user.loading) return <p>Loading…</p>;
  if (user.error) return <p>Error: {user.error.message}</p>;
  return <p>{user()?.name}</p>;
});
```

## Consume async generators

Return an async generator to stream values into the envelope — useful for sockets, feeds, and long-polling:

```tsx twoslash
import { ilha, derived } from "ilha";

const Ticker = ilha(() => {
  const tick = derived(async function* ({ signal }) {
    while (!signal.aborted) {
      yield new Date().toISOString();
      await new Promise((r) => setTimeout(r, 1000));
    }
  });
  return <p>{tick()}</p>;
});
```

On the client, ilha consumes the generator continuously. During async SSR, ilha pulls the first yielded value so it renders inline instead of a loading placeholder. Abort iteration by returning from the loop when `signal` is aborted.

## Cancellation and stale results

Every async derived function receives an `AbortSignal` that aborts when the function is about to re-run or the island unmounts. Pass it to `fetch` or any other cancellable API to avoid stale responses:

```tsx twoslash
import { ilha, state, derived } from "ilha";

const Search = ilha(() => {
  const query = state("");
  const results = derived(async ({ signal }) => {
    const res = await fetch(`/api/search?q=${query()}`, {
      signal,
    });
    return res.json() as Promise<string[]>;
  });

  return (
    <>
      <input bind:value={query} />
      {results.loading ? (
        <p>Searching…</p>
      ) : (
        <ul>
          {results()?.map((r) => (
            <li>{r}</li>
          ))}
        </ul>
      )}
    </>
  );
});
```

If the signal is already aborted before your async work completes, the result is discarded silently. When a derived re-runs, `loading` becomes `true` but `value` retains the previous result until the new one resolves — so you can keep stale content visible while refreshing.

## SSR behavior

During SSR, derived functions are called once. `await Isle.toStringAsync(props)` waits for async values before rendering. `Isle.toString(props)` renders them in the `loading` state immediately.

```ts twoslash
import { ilha } from "ilha";

const MyIsland = ilha<{ userId: number }>(({ userId }) =>
  userId.toString(),
);

const asyncHtml = await MyIsland.toStringAsync({ userId: 1 });
const syncHtml = MyIsland.toString({ userId: 1 });
```

## Hydration snapshots

With `.hydratable()` and a snapshot, derived values are embedded in the server output and restored on the client, so the island renders immediately without re-fetching. Snapshots are positional — values restore by primitive order.

## Notes

- Rejected or thrown async derived work sets `derived.error` on the envelope — it is not routed to `onError()`. Handle failures in the render path.
- Put conditions inside the derived function, not around the `derived()` call.
- Multiple derived entries are independent; each tracks its own dependencies.
