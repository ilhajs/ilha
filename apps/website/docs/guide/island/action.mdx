title: Handle events
description: Handle native events with plain functions, then use action() when you need reactive operation state and cancellation.
---

Pass a function to a lowercase native event prop such as `onclick` or `onsubmit`:

```tsx twoslash
import { ilha, state } from "ilha";

const Counter = ilha(() => {
  const count = state(0);

  const increment = () => {
    count((value) => value + 1);
  };

  return <button onclick={increment}>Count: {count()}</button>;
});
```

Use plain functions for ordinary operations. You do not need a primitive to handle an event, update state, call an API, or run application logic.

## Handle native event data

The handler receives the native browser event. Use `currentTarget` when you need the element that owns the listener:

```tsx twoslash
import { ilha, state } from "ilha";

const NameForm = ilha(() => {
  const message = state("");

  const submit = async (event: SubmitEvent) => {
    event.preventDefault();
    const form = event.currentTarget as HTMLFormElement;
    const name = String(new FormData(form).get("name") ?? "");

    await fetch("/api/profile", {
      method: "POST",
      body: JSON.stringify({ name }),
    });

    message(`Saved ${name}`);
  };

  return (
    <form onsubmit={submit}>
      <input name="name" required />
      <button>Save</button>
      <p>{message()}</p>
    </form>
  );
});
```

Keep event behavior and DOM-specific conversion in the handler. Pass application values to a separate function when you want to reuse the operation:

```tsx twoslash
import { ilha } from "ilha";

const Newsletter = ilha(() => {
  const subscribe = async (email: string) => {
    await fetch("/api/newsletter", {
      method: "POST",
      body: JSON.stringify({ email }),
    });
  };

  return (
    <form
      onsubmit={(event) => {
        event.preventDefault();
        const email = String(
          new FormData(event.currentTarget).get("email") ?? "",
        );
        subscribe(email);
      }}
    >
      <input name="email" type="email" required />
      <button>Join</button>
    </form>
  );
});
```

Start with this form. Add `action()` only when the UI needs to react to the operation itself.

## Track an operation with `action()`

`action()` wraps an operation in a reactive envelope. The returned accessor is callable and exposes:

| Property  | Value                                 |
| --------- | ------------------------------------- |
| `pending` | Whether one or more calls are running |
| `data`    | The latest successful result          |
| `error`   | The latest error, or `undefined`      |

This makes form submission state, loading indicators, success output, and errors available during render:

```tsx twoslash
import { ilha, action } from "ilha";

const ProfileForm = ilha(() => {
  const save = action(async (form: FormData, { signal }) => {
    const response = await fetch("/api/profile", {
      method: "POST",
      body: form,
      signal,
    });

    if (!response.ok) throw new Error("Could not save profile");
    return response.json() as Promise<{ name: string }>;
  });

  return (
    <form
      onsubmit={(event) => {
        event.preventDefault();
        save(new FormData(event.currentTarget));
      }}
    >
      <input name="name" required />
      <button disabled={save.pending}>
        {save.pending ? "Saving…" : "Save"}
      </button>
      {save.error && <p role="alert">{save.error.message}</p>}
      {save.data && <p>Saved {save.data.name}</p>}
    </form>
  );
});
```

The native handler owns the event and payload conversion. The action owns execution state and lifecycle cancellation.

## Use an action as the handler

Use an action directly when its payload is already the native event:

```tsx twoslash
import { ilha, action } from "ilha";

const Form = ilha(() => {
  const submit = action(async (event: SubmitEvent) => {
    event.preventDefault();
    const form = event.currentTarget as HTMLFormElement;
    await fetch("/api", {
      method: "POST",
      body: new FormData(form),
    });
  });

  return (
    <form onsubmit={submit}>
      <input name="name" />
      <button disabled={submit.pending}>
        {submit.pending ? "Saving…" : "Save"}
      </button>
    </form>
  );
});
```

Direct action references are matched by identity in the hydration manifest. This lets server-owned islands reconnect them without invoking the handler during SSR.

## Concurrency guarantees

Multiple concurrent calls share a pending counter. The latest-started call owns `data` and `error`. Previous successful data remains available while a newer call is pending.

## Cancellation

An action receives an `AbortSignal` that aborts when the island unmounts. Pass it to `fetch` or another cancellable API. Ilha ignores later settlements and filters cancellation `AbortError` values.

## Errors

When an action throws or rejects, its `error` property updates and the error routes to [`onError()`](/guide/island/errors) with `source: "action"`.

## SSR behavior

Actions remain idle during SSR. Calling an action during SSR logs a development warning and does not execute the operation.

## Choose the smallest tool

Use a plain function by default. Reach for `action()` when you need at least one of these features:

- Render pending, success, or error state.
- Disable controls while an operation runs.
- Show a loader during form submission.
- Preserve the previous successful result during a refresh.
- Cancel work automatically when the island unmounts.
- Route operation failures through `onError()`.
