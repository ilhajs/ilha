---
title: Run actions
description: Define synchronous or asynchronous island operations with reactive pending, data, and error state.
---

For ordinary operations, use plain functions. Use the `action()` primitive only when you need reactive execution state and lifecycle cancellation — pending, data, and error:

```tsx twoslash
import { action } from "ilha";
// Declared inside an island component (action() is an island primitive).
const save = action(async (form: FormData, { signal }) => {
  const response = await fetch("/save", {
    method: "POST",
    body: form,
    signal,
  });
  return response.json();
});
```

An action accessor is callable and exposes reactive status properties that subscribe the surrounding island render when read:

```ts twoslash
import { action } from "ilha";

const save = action(async (payload: string) => payload.length);

save("hello"); // → 5
save.pending; // → false
save.data; // → number | undefined
save.error; // → Error | undefined
```

## Using actions in a component

```tsx twoslash
import { ilha, state, action } from "ilha";

const Form = ilha(() => {
  const saved = state(false);

  const submit = action(async (event: SubmitEvent) => {
    event.preventDefault();
    const form = event.currentTarget as HTMLFormElement;
    const response = await fetch("/api", {
      method: "POST",
      body: new FormData(form),
    });
    saved(await response.json());
  });

  return (
    <form onsubmit={submit}>
      <input name="name" />
      <button disabled={submit.pending}>
        {submit.pending ? "Saving…" : "Save"}
      </button>
    </form>
  );
});
```

## Direct native event use

Use an action directly as a native event handler when its payload matches the event type:

```tsx twoslash
import { action } from "ilha";

const submit = action(async (event: SubmitEvent) => {
  event.preventDefault();
  // ...
});

// Later, in JSX:
<form onsubmit={submit}>…</form>;
```

Direct action references are matched by identity for the hydration manifest, so server-owned islands can reconnect them.

## Transform event data

Keep DOM-specific conversion in the native handler when an action accepts an application payload:

```tsx twoslash
import { ilha, action } from "ilha";

const Newsletter = ilha(() => {
  const subscribe = action(async (email: string) => {
    await fetch("/api/newsletter", {
      method: "POST",
      body: JSON.stringify({ email }),
    });
  });

  return (
    <form
      onsubmit={(event) => {
        event.preventDefault();
        const email = String(
          new FormData(event.currentTarget).get("email") ?? "",
        );
        subscribe(email);
      }}
    >
      <input name="email" type="email" required />
      <button disabled={subscribe.pending}>
        {subscribe.pending ? "Joining…" : "Join"}
      </button>
    </form>
  );
});
```

The native handler owns event behavior and payload conversion. The action owns the operation and its reactive state.

## Concurrency guarantees

Multiple concurrent invocations are tracked with a pending counter. The latest-started invocation owns `data` and `error`, and previous successful data remains while a newer call is pending. Settlements after unmount are ignored.

## Cancellation

An action's `signal` aborts when the island unmounts. Pass it to `fetch` or other cancellable APIs. On unmount, ilha ignores settlements and filters `AbortError` so cancellation never surfaces as a real error.

## Errors

When an action throws or rejects, its `error` property is set and the error routes to [`onError()`](/guide/island/errors) with `source: "action"`. `AbortError` is filtered automatically.

## SSR behavior

Actions are idle during SSR — the stub does not execute. Calling an action during SSR logs a dev warning and is ignored.

## Plain functions vs actions

Use a plain function for an operation whose result you do not need to render:

```tsx twoslash
import { state } from "ilha";

const count = state(0);
const increment = (amount: number) => {
  count((value) => value + amount);
};
```

Reach for `action()` when you render `pending`, `data`, or `error`, or when you need unmount cancellation.
