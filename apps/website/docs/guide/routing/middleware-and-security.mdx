`@ilha/router` hardens the server-island endpoint by default. This page is the full guard and origin model behind [Server islands](/guide/routing/server-islands).

## Security headers

Both `respond()` and the low-level `httpResponse()` emit sensible security headers by default:

| Header                   | Value         |
| ------------------------ | ------------- |
| `Content-Type`           | `text/html`   |
| `X-Content-Type-Options` | `nosniff`     |
| `Referrer-Policy`        | `no-referrer` |
| `Cache-Control`          | `no-store`    |

A header is added only when the caller has not already set it, so you can override any default by passing `headers`.

```tsx twoslash
import { httpResponse } from "@ilha/router";
const html = "<h1>Hi</h1>";
const nonce = "abc123";
// ---cut---
// Default: nosniff, no-referrer, no-store (see table above).
const res = httpResponse("<h1>Hi</h1>");

// Conservative default CSP via a nonce — pass the same nonce to <script nonce=…>.
const withCsp = httpResponse(html, { cspNonce: nonce });

// Full CSP string wins over the nonce-derived default.
const locked = httpResponse(html, {
  contentSecurityPolicy: "default-src 'self'",
});
```

| Option                  | Behavior                                                                  |
| ----------------------- | ------------------------------------------------------------------------- |
| `status`                | Response status (default `200`).                                          |
| `headers`               | Extra headers, merged over defaults.                                      |
| `cspNonce`              | Emit a conservative default CSP with `'nonce-${nonce}'` for `script-src`. |
| `contentSecurityPolicy` | Full CSP string; overrides the nonce-derived default.                     |

Prefer `respond()` when you are rendering a route — it runs the full render + head + headers pipeline. Reach for `httpResponse()` when you already have the HTML and only need a correctly-headered `Response`.

## Deny-by-default frame endpoint

In **production**, the internal frame endpoint is **denied unless you install a guard**:

| Endpoint        | Serves                                      | Method | Default when unguarded |
| --------------- | ------------------------------------------- | ------ | ---------------------- |
| `/__ilha/frame` | Re-render of a server island or server page | POST   | Denied (`403`)         |

An unguarded frame endpoint would let anyone re-render any server island by id — if an island's state holds private data you must install a session check. The **dev** middleware stays permissive unless you register a guard, so local iteration works out of the box.

## Installing guards

Register guards once at server startup for production, via the shared registry:

```ts twoslash
import { setFrameAuth, setFrameGuard } from "@ilha/router/ssr";

const expectedToken = process.env.CSRF_TOKEN;
function isSignedIn(_request: Request) {
  return true;
}
// ---cut---
// Gates /__ilha/frame in production; without this the endpoint returns 403.
setFrameGuard((request) => {
  if (!isSignedIn(request))
    return new Response("Unauthorized", { status: 401 });
});

// Optional: explicit trusted origins and a CSRF verifier for the frame POST.
setFrameAuth({
  trustedOrigins: ["https://app.example.com"],
  // Verify a per-session token issued by your server (double-submit cookie or
  // synchronizer token), compared in constant time. Never use a build-time
  // environment variable or literal string — anything shipped to the browser
  // is public and cannot be a CSRF secret.
  csrf: (request) =>
    request.headers.get("x-csrf") === expectedToken,
});
```

In **dev**, configure the guard through the plugin options instead — pass `frameGuard` to the pages plugin.

### `setFrameAuth`

Tuning the frame-auth policy:

| Option           | Type                   | Behavior                                                                                                                        |
| ---------------- | ---------------------- | ------------------------------------------------------------------------------------------------------------------------------- |
| `defaultAction`  | `"open" \| "deny"`     | `"deny"` is the default. `"open"` opts out of deny-by-default (not recommended).                                                |
| `trustedOrigins` | `string[]`             | Explicit origins to accept for frame origin checks. Otherwise the `Origin` header is compared against the request's own `Host`. |
| `csrf`           | `(request) => boolean` | Extra verifier for the frame POST — covers non-browser callers that send no `Origin` header.                                    |

## What is forwarded

The middleware forwards only `cookie`, `authorization`, and `user-agent` headers to the scoped frame render. It deliberately does **not** forward a client-supplied `x-forwarded-for` header — it is spoofable and must not be trusted for IP checks. If you relied on it for IP-based decisions, move that check to a trusted proxy layer instead.

## Validation and status clamping

- Frame bodies are streamed with a hard **16&nbsp;KiB cap**; oversized bodies return `413`.
- Frame paths are validated and **fail closed** — an invalid path returns `400` instead of falling back to `/`.
- Failures are typed: the frame render returns a `FrameError` result, and `redirect()` coerces invalid statuses to `302`; `error()` coerces invalid statuses to `500` (silently).
- Render failures surface as `"frame failed"` — error details are never leaked to clients in production.
