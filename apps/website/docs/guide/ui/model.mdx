`@ilha/model` is Effect UI's component runtime inside Ilha islands. Each component owns a Model, a message loop, and a pure view. Side effects run as Commands, ongoing work as Subscriptions, remote data as Queries.

It is a separate package from `ilha`. Add it when one island owns enough messages to deserve a single loop per component. Plain `atom()` keeps working for everything else.

## Install

```package-install
@ilha/model
```

`ilha` and `effect` are peer dependencies.

## Define a component

`defineComponent` takes Schemas for `props`, `model`, `message`, and optional `events`, plus `queries`, `slots`, `reads`, and `shares`. `make` takes pure `init` / `update` / `view` and keyed `subscriptions`.

```tsx twoslash
import { Effect, Schema } from "effect";
import { Command, defineComponent, TaggedEnum } from "@ilha/model";

const CounterMessage = TaggedEnum({
  ClickedAdd: { amount: Schema.Number },
  ClickedReset: {},
  CompletedReset: {},
});

const DelayReset = Command.make("delay-reset", { args: {} }, () =>
  Effect.succeed(CounterMessage.CompletedReset())
);

const CounterDef = defineComponent({
  name: "Counter",
  props: Schema.Struct({ label: Schema.String }),
  model: Schema.Struct({ count: Schema.Number }),
  message: CounterMessage,
  events: TaggedEnum({ Reached: { count: Schema.Number } }),
});

export const Counter = CounterDef.make({
  init: () => ({ count: 0 }),
  update: {
    ClickedAdd: ($, { amount }) => $.evolve({ count: (c) => c + amount }),
    ClickedReset: ($) => $.run(DelayReset()),
    CompletedReset: ($) =>
      $.evolve({ count: 0 }).emit({ _tag: "Reached", count: 0 }),
  },
  view: (h, model) => (
    <div>
      <span>{h.props.label}</span>
      <output>{model.count}</output>
      <button onclick={h.send(CounterMessage.ClickedAdd({ amount: 1 }))}>
        +1
      </button>
      <button
        disabled={h.isRunning(DelayReset)}
        onclick={h.send(CounterMessage.ClickedReset())}
      >
        Reset
      </button>
    </div>
  ),
});
```

`update` is a whole-message function, a record with one handler per tag, or `Def.update` slices. A handler may return a bare Model. `$` offers `set`, `evolve`, `run`, `emit`, `send(owner)` / `send("self")`, `combine`, `loadMore`, `reset`, and `viewTransition`. `init` returns the first Model plus optional start-up Commands; its Commands run once per client mount (never during server rendering) and its emits are dropped on hydration. `view`, `init`, `update`, `subscriptions`, `shares.value`, and query `args` must be pure: never call an Ilha primitive (`atom`, `watch`, `when`) inside them.

`h` in `view` is Ilha's `HFn` plus model extras: `props`, `children`, `reads`, `queries`, `previous`, `patched`, `slots`, `keepAlive`, `isRunning(cmd, ...group)`, `id(name, key?)`, `send`, `mount`, and `ref`. `h.send(msg | (event) => msg | undefined, { preventDefault })` returns an Ilha event handler; `preventDefault: true` prevents only when a message was produced, `"always"` prevents regardless. `h.id` derives an id from the instance path, so server and client agree.

Mount through a root: `mount(host, Component.root(Counter, { label: "Likes" }))` or `await renderToString(Component.root(Counter, { label: "Likes" }))`. A root's failure goes to the island's `onError`.

### Prefer typed `h()` when requirements matter

`h()` calls return `VNode<ComponentRequires<type> | Requires<children…>>`, so a component that needs a service is checked where it runs: `mount` accepts `never | Client`, `renderToString` accepts only `never`. A JSX expression is `View<unknown>`, so it contributes no static requirements and its services are checked at run time instead: a missing required owner or service fails the instance with a message naming the service and the path (a missing `Client` during server rendering also says to wrap it in `Component.clientOnly`). When compile-time requirement checks matter, write views with typed `h()`.

## Call children

Children are components with `key`, nested `props`, `onEmit`, `onFailure`, `fallback`, `slots`, and `view` for headless children. Paths are `Name[key]` segments; a second unkeyed child of the same component or two children at one path fails the author, while branch swaps at one path keep the instance.

```tsx
<Counter
  key="likes"
  props={{ label: "Likes" }}
  onEmit={{ Reached: ({ count }) => PageMessage.ReachedCounter({ count }) }}
  onFailure={() => PageMessage.FailedCounter()}
  fallback={(result) => <p>Counter unavailable</p>}
/>
// or h(Counter, { props: { label: "Likes" }, onEmit: … }); keys only work through JSX
```

`onEmit`, `onFailure`, and `fallback` resolve against the author: the instance whose `view` (or `view` closure) wrote the child vnode, wherever it ends up. A throw in `init`, `update`, `view`, `parts`, `shares`, `subscriptions`, or query `args` — or a Command, Subscription, or Mount defect, an unhandled Layer failure, or a missing owner or service — fails the instance: it logs `Failed`, closes the scope, renders the author's `fallback`, and schedules `onFailure`. The failure stays until the key changes; the rest of the island keeps running.

`Component.lazy(name, load)` splits a child into its own module. Declare it once at module scope and share it across islands: `preload()` starts the load without rendering, the first rendered child starts it, `fallback` gets `Initial` while loading and `Failure` if the load fails, and a failed load retries on the next mount. On the server the render awaits the load; on the client the fallback draws until the module arrives.

`h.keepAlive((s) => …)` and `h.keepAlive(alive, (s) => …)` keep children alive across renders with literal keys. A kept child keeps its Model, query results, running Commands, Subscriptions, and Layer — but its DOM is removed and rebuilt from the kept Model when it is drawn again. Uncontrolled DOM state, scroll, and focus are not preserved.

Slots place author content: declare `slots: [...]`, render `h.slots.name`, and pass `slots={{ name: content }}` at the call site. Slot content belongs to the author, a slot is placed at most once per render, and the slot's path segment is `[name]`.

## Share state between components

Owners share state down the tree: `shares` with `value(model, props, reads)`, `schema`, `receives`, and `collects`; `reads` entries with `owner`, `optional`, `report`, and `onChange`; `$.send` to message the nearest live owner above (or `send("self")` for the nearest instance of the sender's own kind). Owners resolve through a hidden context per owner definition, so a missing required owner is a run-time failure of the reader, not a type error. `Component.Shared.Of<typeof X>` exists as a type for documentation and tests.

Headless components split logic from markup: `parts(p, model)` with `p.props`, `p.reads`, `p.queries`, `p.isRunning`, `p.id`, `p.part`, and `p.child`, plus a consumer `view` closure owned by the consumer. Decorate an Ilha VNode — `listbox.trigger(<button>Open</button>)` — and merges follow the part algebra: part attributes win, token-list attributes (`class`, `rel`, `aria-*` id lists) are added and deduplicated, `attr: undefined` removes an attribute, and a part can't set `key` or apply another part. Handlers become layers, deepest owner first and the consumer last; applying a part outside its owner's view or setting a conflicting event option fails in dev mode.

## Provide services

`Component.provide` scopes an Env down a hidden context: curried, array, props-function, and keyed forms, plus `local` and a required `onFailure` when the Layer can fail. Layers build once per Env × Layer, reference-counted and shared through `Layer.CurrentMemoMap`; the inner provide wins. Rendering never waits for the build, but Commands and Subscriptions do. Layers never build on the server, since Commands and Subscriptions never run there. A service still missing at run time fails the instance and names the service and the path.

`Feature.Service` checks the contract with `toLayer` and renders with `render(h, { key, props, onEmit, fallback })`, where `fallback` is required.

## Run Commands

`Command.make(name, { args, mode, group, stream }, body)` defines an Effect (or, with `stream: true`, a Stream) whose body can't fail: expected failures become messages, a defect or unmatched typed failure fails the instance. `Command.Service` builds query-aware Commands with `toLayer`. Combinators: `map`, `as`, `asNoop`, `match`, `afterRefetch`, `interrupt`. Modes are `concurrent`, `switch` (a new issue cuts an awaiting run), and `queue` (issues run in order); `group` scopes the mode, and `h.isRunning(Cmd, ...group)` reports queued, running, awaiting, or stopping runs until the fiber exits.

No Command runs on the server. `init` Commands run on the client after hydration or adoption; `update` Commands issued during the server render log `CommandDropped`.

## Subscribe to streams

```ts
import { Subscription } from "@ilha/model";

const Ticks = Subscription.make("ticks", model.on, (on) =>
  on ? TicksStream : Stream.empty
);
```

`Subscription.make(name, stream)` runs a fixed stream; `make(name, deps, build)` rebuilds only when the deps change. Keys compare on every pass: removed keys stop before new keys start, an existing key never restarts, an ended Stream stays stopped until its key leaves and returns, and duplicate keys fail the instance. `Subscription.direct` attaches synchronously to a host event source instead of running a Stream.

`DomSubscription.onDocument`, `onWindow`, `onCustomEvent`, `onAnimationFrame`, and `shortcuts` cover document, window, custom, and animation-frame events plus `Keyboard.shortcuts` with the full matching rules, over the `GlobalEvents` and `AnimationFrames` services (whose defaults never fire; the island mount provides the browser versions). One listener runs per target, event, and phase. Nothing listens on the server.

## Attach mounts and refs

`Mount.make` / `makeStream` attach work to an element: `h.mount(issued)` returns an Ilha `ref` prop, the body starts after commit, same-name new args publish to `changes`, a different name restarts the mount, a render without the mount stops it, and an element takes one mount. A defect fails the instance. Mounts never run on the server. `Dom.ref(name, tag)` plus `h.ref(ref)` names an element for `DomCommand` (`focus`, `blur`, `scrollIntoView`, `measure`, `select`, `requestSubmit`, `showPicker`); `DomFiles` (readers, `pick`) and `DomImages` (`load`) cover files and images.

## Load remote data with Query

Define a query, provide its fetcher, and declare per-component `queries`:

```ts
import { Query } from "@ilha/model";

class GetUser extends Query.Service<GetUser>()("users/get", {
  args: { id: Schema.String },
  success: User,
  error: LoadError,
  staleTime: "30 seconds",
  tags: [Query.Tag("users")],
}) {}

// in defineComponent: queries: { user: { query: GetUser, args: ({ model }) => ({ id: model.id }) } }
// in view: h.queries.user — an AsyncResult; h.previous / h.patched beside it
// in update: $.queries, $.loadMore("feed"), $.reset("feed")
```

Queries carry `staleTime`, `idleTimeToLive`, `refetchInterval`, and `tags`, with `get`, `prefetch`, `invalidate`, `changes`, `peek`, and `entry` plus infinite queries (`InfiniteService`, `loadMore`, `reset`). `invalidates` runs on every exit of a started run; `optimistic` patches and `writes` apply around it, with `afterRefetch` mapping the result. Component entries support `query` / `queryMany`, `debounce`, and `onChange`. The cache lives once per island registry; server rendering uses a per-request cache, ships settled entries in the island snapshot, and gives the client a fetch-free window until adoption completes. `Redacted` entries are never shipped.

A Model or query Schema holding `Schema.Redacted` anywhere is never snapshotted: its instance renders on the server from `init` and rebuilds on the client, with a one-time warning per component.

## Compose apps from components

`Component.root(App, props)` turns a model component into a plain Ilha component for `mount`, `renderToString`, and island adapters, keeping any `Client` requirement in the root. `Component.clientOnly(C, { fallback })` renders `fallback` on the server and `C` on the client (after hydration), removing `Client` from the requirements.

Client-only apps skip the server entirely:

```ts
import { mount } from "ilha";
import { Component } from "@ilha/model";

mount(host, Component.root(App, props));
```

## Test with Story, Scene, or Play

Pick one kind per test:

| Kind | Runs | Use it to |
| --- | --- | --- |
| `Story` | Pure `update`, no runtime, Layers, host, or view | Prove message logic: `send` messages, resolve pending Commands as data, assert Model, emits, sends, interrupts |
| `Scene` | Pure rendered view, children as leaves | Prove rendering and interaction: `click`, `fire`, `type`, `keydown`, `childEmit`, `childFailure`, `givenChild`, `expect*`; no Model is shown |
| `Play` | Real renderer in happy-dom under `TestHost.layer` | Prove integration: real Layers, children, Commands, clock, host signals, and DOM locators (roles, names, labels) |

Story and Scene follow the acknowledgement rule (pending Commands, events, and sends must be settled or kept). `Story.fromLog` replays a devtools export (`Replay` / `Divergence`). `Ssr.ssr(component, props)` runs `renderToString`, mounts with hydration in a fresh document, and fails with `SsrError` for an unadopted or drifted Model, a rebuilt node, a query that doesn't round-trip, a fetch inside the fetch-free window, a waiting Layer, or any reported problem. Fakes: `TestQuery`, `TestFiles`, `TestImages`, `TestHost`.

```ts
import { Effect } from "effect";
import { Story } from "@ilha/model/test";

const count = await Effect.runPromise(
  Effect.scoped(
    Effect.map(Story.make(Counter, { label: "Likes" }), (s) => {
      s.send(CounterMessage.ClickedAdd({ amount: 1 }));
      return s.model.count;
    })
  )
);
expect(count).toBe(1);
```

`@ilha/model/validation` adds field rules, derived field state, and submit gating for forms.

## Follow the MessageLog in devtools

`MessageLog` records every entry with causality, instance numbering, and `boundary`, off by default and costing nothing when off. Sinks: `memory`, `fanout`, `fanoutAll`, `makeEncoded`, `socket`; Wire v1 encoding with placeholders, `maxEntryBytes`, and `Redacted` redaction.
