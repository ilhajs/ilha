`@ilha/model` holds one island's state in a single model. You describe transitions in `update`, side effects as return values, and rendering in `view`.

It is a separate package from `ilha`. Add it when one island owns enough messages to deserve a single loop. Plain `atom()` keeps working for everything else.

## Install

```package-install
@ilha/model
```

`ilha` and `effect` are peer dependencies.

## Define a component

Name the component and give it a model Schema, a message union, and optional props and events Schemas. `make` takes the implementation and returns an ordinary Ilha component: each instance owns its own model atom, and a child rerenders without rerunning its parent.

```tsx twoslash
import { Effect, Schema } from "effect";
import { Command, defineComponent } from "@ilha/model";

const Msg = Schema.TaggedUnion({
  ClickedAdd: { amount: Schema.Number },
  ClickedReset: {},
  CompletedReset: {},
});
const DelayReset = Command.make("DelayReset", { mode: "switch" }, () =>
  Effect.sleep("1 second").pipe(Effect.as(Msg.cases.CompletedReset.make({})))
);
export const Counter = defineComponent({
  name: "Counter",
  props: Schema.Struct({ label: Schema.String }),
  model: Schema.Struct({ count: Schema.Number }),
  message: Msg,
  events: Schema.TaggedUnion({ Reached: { count: Schema.Number } }),
}).make({
  init: () => ({ count: 0 }),
  update: {
    ClickedAdd: ($, { amount }) => $.evolve({ count: (c) => c + amount }),
    ClickedReset: ($) => $.run(DelayReset()),
    CompletedReset: ($) =>
      $.set({ count: 0 }).emit({ _tag: "Reached", count: 0 }),
  },
  view: (h, model) => (
    <div>
      <span>{h.props.label}</span>
      <output>{model.count}</output>
      <button onclick={h.send(Msg.cases.ClickedAdd.make({ amount: 1 }))}>
        +1
      </button>
      <button
        disabled={h.isRunning(DelayReset)}
        onclick={h.send(Msg.cases.ClickedReset.make({}))}
      >
        Reset
      </button>
    </div>
  ),
});
```

Mount it like any component: `mount(host, () => <Counter props={{ label: "Likes" }} />)`. There is no root helper. `props` is required exactly when the component declares a `props` Schema; `key` is Ilha's own.

Name messages for their cause (`ClickedSave`, `GotUser`). Build them with `Msg.cases.X.make(...)`: messages are plain Schema data, never callbacks or class instances.

## Update with `$`

`init` takes `$` and the props and returns the first model, or a step when start-up work or an opening event is needed. `update` is an exhaustive record with one handler per message tag. Each handler takes `$` and the message payload, and returns a bare model or a step:

- `$.model` is the current model (update only); `$.props` is the current props.
- `$.set(model)` replaces the model; `$.evolve({ count: (c) => c + 1 })` patches fields, each a value or an updater.
- `$.run(...)` issues commands; `$.emit(event)` reports to `onEmit` after the model commits.
- Steps chain: `$.set(...).run(...).emit(...)`.

## View with `h`

`view` takes Ilha's `h` plus three helpers, and the current model. `h.props` reads the props; `h.send(...)` returns an event handler — pass a message, or a mapper from the handler argument to a message, where returning `undefined` sends nothing; `h.isRunning(command)` is reactive and flips the view while that command runs.

## Children

A child is an ordinary component use: pass `props`, and map its events to a parent message through `onEmit`. The parent never touches the child model; each instance keeps its own atom.

```tsx twoslash
import { Schema } from "effect";
import { defineComponent } from "@ilha/model";

const ChildMsg = Schema.TaggedUnion({ Clicked: {} });
const Child = defineComponent({
  name: "Child",
  model: Schema.Struct({ n: Schema.Number }),
  message: ChildMsg,
  events: Schema.TaggedUnion({ Reached: { n: Schema.Number } }),
}).make({
  init: () => ({ n: 0 }),
  update: {
    Clicked: ($) =>
      $.set({ n: $.model.n + 1 }).emit({ _tag: "Reached", n: $.model.n + 1 }),
  },
  view: (h, model) => (
    <button onclick={h.send(ChildMsg.cases.Clicked.make({}))}>{model.n}</button>
  ),
});
const PageMsg = Schema.TaggedUnion({ ChildReached: { n: Schema.Number } });
export const Page = defineComponent({
  name: "Page",
  model: Schema.Struct({ total: Schema.Number }),
  message: PageMsg,
}).make({
  init: () => ({ total: 0 }),
  update: {
    ChildReached: ($, { n }) => $.evolve({ total: (t) => t + n }),
  },
  view: (h, model) => (
    <div>
      <p>{model.total}</p>
      <Child
        key="likes"
        onEmit={h.send((e) => PageMsg.cases.ChildReached.make({ n: e.n }))}
      />
    </div>
  ),
});
```

Give each child a `key` so its state stays with it across parent rerenders.

## Commands

A command is an `Effect` that resolves to a follow-up message or nothing. Declare it with `Command.make`, call it to issue, and hand the issue to `$.run`. The body takes `(args)` — the call takes the same args, and a zero-arg body makes a zero-arg call — and resolves to `Message | void` with a `never` error channel: map every expected failure into a message. `{ mode: "switch" }` cuts the instance's running issue when a new one starts; the default `concurrent` lets every issue land.

```tsx twoslash
import { Effect, Schema } from "effect";
import { Command, defineComponent } from "@ilha/model";

const Msg = Schema.TaggedUnion({
  GotUser: { name: Schema.String },
  Search: { query: Schema.String },
});
const FetchUser = Command.make(
  "FetchUser",
  { mode: "switch" },
  ({ query }: { query: string }) =>
    Effect.succeed(Msg.cases.GotUser.make({ name: `hit for ${query}` }))
);
export const Search = defineComponent({
  name: "Search",
  model: Schema.Struct({ name: Schema.String, query: Schema.String }),
  message: Msg,
}).make({
  init: () => ({ name: "", query: "" }),
  update: {
    Search: ($, { query }) => $.evolve({ query }).run(FetchUser({ query })),
    GotUser: ($, { name }) => $.evolve({ name }),
  },
  view: (h, model) => (
    <div>
      <p>{h.isRunning(FetchUser) ? "Searching…" : model.name}</p>
      <button onclick={h.send(Msg.cases.Search.make({ query: "ab" }))}>
        Search
      </button>
    </div>
  ),
});
```

`h.isRunning` takes the command definition and rerenders when its issues start and end. A defect — a throw, a `die`, a missing service — is logged through the Effect logger and the instance keeps running.

Nothing runs during server rendering. Commands from `init` run on the client after mount and after hydration, and every running issue is interrupted on unmount.

## Subscriptions

A subscription is a stream the instance runs while it asks for it. Declare it with `Subscription.make`, either from a stream or from deps plus a builder; deps compare with `Equal.equals`, so a change restarts the stream, and removing the entry stops it. Duplicate names throw.

```tsx twoslash
import { Schema, Stream } from "effect";
import { Subscription, defineComponent } from "@ilha/model";

const Msg = Schema.TaggedUnion({ Tick: {} });
export const Clock = defineComponent({
  name: "Clock",
  props: Schema.Struct({ on: Schema.Boolean }),
  model: Schema.Struct({ count: Schema.Number }),
  message: Msg,
}).make({
  init: () => ({ count: 0 }),
  update: {
    Tick: ($) => $.evolve({ count: (c) => c + 1 }),
  },
  view: (h, model) => <p>{model.count}</p>,
  subscriptions: (_model, props) => [
    Subscription.make(
      "ticks",
      (_model: unknown, p: { readonly on: boolean }) => p.on,
      (on) =>
        on
          ? Stream.tick("1 second").pipe(
              Stream.map(() => Msg.cases.Tick.make({}))
            )
          : Stream.empty
    ),
  ],
});
```

Like commands, subscriptions never run on the server; a stream's error channel is `never`, so convert failures into messages inside the stream.

## Services

Commands and subscriptions read services from one layer per component per mounted root; instances of that component share its services. Name it in `make`; command bodies use its services with no extra wiring. A command that needs a service outside the layer does not compile.

```tsx twoslash
import { Context, Effect, Layer, Schema } from "effect";
import { Command, defineComponent } from "@ilha/model";

const Msg = Schema.TaggedUnion({
  Greet: {},
  Greeted: { text: Schema.String },
});
const Greeter = Context.Service<{ greet: (name: string) => string }>("Greeter");
const SayHi = Command.make("SayHi", () =>
  Effect.map(Effect.service(Greeter), (greeter) =>
    Msg.cases.Greeted.make({ text: greeter.greet("you") })
  )
);
export const Hello = defineComponent({
  name: "Hello",
  model: Schema.Struct({ greeting: Schema.String }),
  message: Msg,
}).make({
  init: () => ({ greeting: "" }),
  update: {
    Greet: ($) => $.run(SayHi()),
    Greeted: ($, { text }) => $.set({ greeting: text }),
  },
  view: (h, model) => (
    <p>
      {model.greeting}
      <button onclick={h.send(Msg.cases.Greet.make({}))}>Greet</button>
    </p>
  ),
  layer: Layer.succeed(Greeter, { greet: (name) => `Hello, ${name}!` }),
});
```

## Snapshot and hydrate

The `model` Schema is also the snapshot codec: the model encodes into the island snapshot on the server and decodes on hydration. Keep the model Schema-shaped — richer values round-trip exactly when the Schema describes them.

## Errors

Throws in `init` and `view` travel Ilha's normal error path: the nearest [`<ErrorBoundary>`](/guide/ui/context-and-errors#error-boundaries) renders its fallback, or `mount`'s `onError` sees them. An `update` throw and Command/Subscription defects are logged instead, and the instance keeps its last model. There is no failure API on top.

## Test with Story

`Story` from `@ilha/model/test` drives a component synchronously: no Effect, no DOM. It runs `init` — recording its commands without executing them — and exposes the model, `send`, emitted events in order, and pending command issues as `{ name, args }[]`. `resolve` drops the oldest pending issue of a command, then sends a message when given one.

```tsx twoslash
import { expect, test } from "bun:test";
import { Effect, Schema } from "effect";
import { Command, defineComponent } from "@ilha/model";
import { Story } from "@ilha/model/test";

const Msg = Schema.TaggedUnion({
  ClickedReset: {},
  CompletedReset: {},
});
const DelayReset = Command.make("DelayReset", () =>
  Effect.succeed(Msg.cases.CompletedReset.make({}))
);
const Counter = defineComponent({
  name: "Counter",
  model: Schema.Struct({ count: Schema.Number }),
  message: Msg,
  events: Schema.TaggedUnion({ Reached: { count: Schema.Number } }),
}).make({
  init: () => ({ count: 0 }),
  update: {
    ClickedReset: ($) => $.set({ count: 7 }).run(DelayReset()),
    CompletedReset: ($) =>
      $.set({ count: 0 }).emit({ _tag: "Reached", count: 0 }),
  },
  view: (h, model) => (
    <button onclick={h.send(Msg.cases.ClickedReset.make({}))}>
      {model.count}
    </button>
  ),
});
test("reset completes through the story", () => {
  const story = Story.make(Counter);
  story.send(Msg.cases.ClickedReset.make({}));
  expect(story.model).toEqual({ count: 7 });
  expect(story.commands.map((c) => c.name)).toEqual(["DelayReset"]);
  story.resolve(DelayReset, Msg.cases.CompletedReset.make({}));
  expect(story.model).toEqual({ count: 0 });
  expect(story.emitted).toEqual([{ _tag: "Reached", count: 0 }]);
});
```

## Watch it run

Model islands record every message once the devtools page script loads: the message, the fields it changed, and how many commands it started. Select the island in the panel, or attach your own recorder in a test:

```ts
import { attachModelRecorder } from "@ilha/model";

const detach = attachModelRecorder((record) => {
  console.log(record.message, record.before, record.after, record.commands);
});
detach();
```

Each record carries the raw `message`, the model `before` and `after`, the number of `commands` started, and the instance's model atom as `instance`, which you can match against `atomsOf(id)` from `ilha/debug`. See [Read the message log](/guide/devtools#read-the-message-log).
