description: Render HTML with renderToString and activate it with mount.

A component returns JSX. You turn that into HTML on the server and into a live tree in the browser.

| API | Env | Output |
| --- | --- | --- |
| `await renderToString(component)` | Server | HTML plus snapshot wrap |
| `await renderToString(component, { markers: false })` | Server | Inner HTML only |
| `mount(el, component)` | Client | Live tree |
| `mount(el, component, { hydrate: true })` | Client | Hydrate existing HTML |

## Return a view

Prefer JSX. Strings become text nodes.

```tsx twoslash
const A = () => <p>Hello</p>;
const B = () => "hello";
```

## Server render

```tsx twoslash
import { atom, renderToString } from "ilha";

const Counter = () => {
  const count = atom(0);
  return <p>{count}</p>;
};

const html = await renderToString(Counter);
```

Default output looks like:

```html
<div data-ilha data-ilha-state='{"v":[0]}'>
  <p>0</p>
</div>
```

| Option           | Default | Meaning                                      |
| ---------------- | ------- | -------------------------------------------- |
| `snapshot`       | `true`  | Embed atom values for hydration              |
| `markers`        | `true`  | Wrap in `<div data-ilha>`                    |
| `timeout`        | none    | Serialize after this many ms even if busy    |
| `captureActions` | `false` | Probe event handlers for server-action calls |

Pass `{ markers: false }` when a host already exists. With both `markers: false` and `snapshot: false`, the output can never hydrate, so `renderToString` also drops the hole hosts (`<span data-ilha-slot>`) and emits plain markup.

`renderToString` builds HTML without a DOM. It runs in Node, Bun, and edge runtimes with no polyfill.

## Mount

```tsx twoslash
import { mount } from "ilha";

const App = () => <p>Hello</p>;

const root = document.getElementById("app");
if (root) {
  const unmount = mount(root, App);
}
```

## Hydrate

If the host contains `[data-ilha]` markup from `renderToString`, pass `hydrate: true`:

```tsx twoslash
import { mount } from "ilha";

const App = () => <p>Hello</p>;

const root = document.querySelector("[data-ilha]");
if (root) mount(root, App, { hydrate: true });
```

Hydration restores atom snapshots in declaration order, then attaches events. Your component can return an element, a component, or a `Fragment` at the root. Ilha morphs the first client render into the server markup, so the nodes stay in place and keep what a user typed before hydration. An element root whose tag differs from the server markup logs a warning and does a full mount.

### Wait for a rerender

`mount()` returns `unmount`. To learn when the DOM reflects an update, pass `onIdle`. It runs after the first paint and again each time pending rerenders, async components, and watchers settle:

```tsx twoslash
import { mount } from "ilha";

const App = () => <p>Hello</p>;
declare const root: HTMLElement;
// ---cut---
mount(root, App, {
  onIdle: () => {
    console.log("DOM is up to date");
  },
});
```

Atom updates rerender in a microtask, so the DOM changes right after the `set()` call returns, not during it.

## Wrap a vanilla library

Some libraries own their DOM node: maps, editors, charts. You grab the node with `ref`, build the instance on mount, and destroy it on the `null` call:

```tsx twoslash
declare const createMap: (el: HTMLDivElement) => { destroy: () => void };

const MapView = () => {
  let map: { destroy: () => void } | null = null;
  return (
    <div
      class="map"
      ref={(el) => {
        if (el) {
          map = createMap(el);
        } else {
          map?.destroy();
          map = null;
        }
      }}
    />
  );
};
```

Each rerender calls the previous `ref` with `null`, then the new `ref` with the element in the document, so always route teardown through the `null` branch. If code outside a `ref` fills an element's children, mark the element with `data-morph-preserve="children"` so rerenders leave that content alone. See [Keep user state across rerenders](/guide/ui/templating#keep-user-state-across-rerenders).

Before you mount a second tree on the same host, call the first `unmount()`:

```ts twoslash
import { mount } from "ilha";

declare const App: () => string;
declare const root: HTMLElement;
// ---cut---
let unmount = mount(root, App);
unmount();
unmount = mount(root, App);
```

Skipping the first `unmount()` leaves two trees — and two `ref` callbacks — fighting over one node.
