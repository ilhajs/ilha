Most event handlers are plain functions. Reach for the `action()` primitive only when an operation needs reactive status — `pending`, `data`, or `error` — or cancellation. A save-to-server call is the classic case:

```tsx twoslash
import { ilha, state, action } from "ilha";

const Counter = ilha(() => {
  const count = state(0);
  const save = action(async (value: number) => {
    await fetch("/api/count", {
      method: "POST",
      body: JSON.stringify({ value }),
    });
    return value;
  });

  return (
    <button
      onclick={async () => {
        const next = count() + 1;
        count.set(next);
        await save(next);
      }}
      disabled={save.pending}
    >
      Increase{save.pending ? "…" : ""}
    </button>
  );
});
```

The button reads `save.pending` to disable itself and show progress while the request is in flight — state a plain function cannot expose.

## Plain functions first

For updates that need no status tracking, skip `action()` entirely:

```tsx twoslash
import { ilha, state } from "ilha";

const Counter = ilha(() => {
  const count = state(0);
  const increase = () => count.update((value) => value + 1);

  return <button onclick={increase}>Increase</button>;
});
```

Use [`action()`](/guide/island/action) when you need `.pending` / `.data` / `.error` or cancellation; use a plain function for everything else.
